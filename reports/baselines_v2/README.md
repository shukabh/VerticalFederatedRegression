Resolves the paper's two check items on vertical full-record SSP (Section "Two further baselines"; check items #13 and
#14 of `paper/main.tex` at 4447418) with the defaults approved for them. Threat model as everywhere: honest-but-curious.
Paper text: `paper/drafts/fullrecord.tex` (old -> new blocks for `paper/main.tex`; both check items removed). Proofs:
`docs/proofs/stats_s7_s10.tex`, Lemma S10d and Lemma S10e (built into `docs/proofs/stats_proofs.pdf` and the appendix).
All numbers, old and new: [`key_numbers.md`](key_numbers.md).

## A. Check #14: the sensitivity for a block of dimension one is now exact (decision: switch to enumeration)

**Before.** Proposition `prop:sens_full` was computed numerically (dense grid + bounded local search, rounded up by a
relative 1e-12). Theorem S10c (Part B) gives the exact value by enumeration only when both of R's and O's blocks have
dimension >= 2; for a block of dimension 1 it is only a conservative bound.

**Now.** `experiments/baselines/sens_full.py: delta_full` is exact in both cases, in the style of `vfr/dp.py:
delta_rep` (enumeration of the stationary points, no search):

- both blocks of dimension >= 2: Theorem S10c (`sup2_closed`, moved here from `experiments/proofs_check`);
- one block of dimension 1 (`sup2_dim1`): **Lemma S10d** (new, proved in `docs/proofs/stats_s7_s10.tex`). The bracket
  is exact for a scalar block; it is convex in lambda^2 along (u, u') -> lambda (u, u') and (y, y') -> lambda (y, y'),
  so with the record-exchange and sign symmetries a maximizer lies on one of five faces of the box of (u, u', y, y');
  on each face the bracket is piecewise polynomial in at most two variables (pieces cut by the lines a = +-2o) and its
  maximum is at a vertex, at a stationary point on an edge (univariate polynomial), or at an interior stationary point
  of a piece (resultant of the two partials). The code enumerates this finite set with exact rational coefficients
  (sympy), exact real-root isolation and 60-digit evaluation, and refuses if a resultant vanishes identically. The
  range of the scalar block is enlarged to the next double above sqrt(R_u), so the value is an upper bound.
- both blocks of dimension 1: refused (`NotImplementedError`; no dataset needs it). A block x_O of dimension 1 with R's
  block of dimension >= 2 is handled by symmetry.

`delta_full_grid` keeps the earlier numerical value for cross-checks; `delta_full_info` also returns the method and
the maximizer.

**Which datasets.** Two of the 29 have d_R = 1: **3droad and tamielectric** (d = 3). The paper's check item named
only tamielectric; the Part B remark after Theorem S10c said "only one"; both are corrected.

**Result.** On every bound vector of the benchmark (29 datasets x 10 folds, block normalization, and the unit bounds of
joint normalization: 319 vectors, 22 of them dimension-1) the exact value agrees with the numerical one to 1.6e-15
relative (8.9e-16 on the dimension-1 vectors) - the grid had found the maximum, and the 1e-12 safeguard is kept. So
**no reported number changes**: the re-run benchmark reproduces every fold value to 9e-16, every paired verdict and
every gap, and the tables regenerated by `tables_base.py` are byte-identical (key_numbers.md B). The value of Theorem
S10c that the check item called conservative is indeed above the exact value on these datasets, by 0-16% (tamielectric,
block norm: Delta 6.0151 vs 5.9999, Delta_G 3.2660 vs sqrt(10) = 3.1623; joint norm: Delta_G 2.4495 vs 2.1213).

Checks (`python experiments/baselines/sens_full.py check` -> `sens_full_check.json`): (i) R's row fixed reproduces
`dp.delta_rep`/`dp.delta_G` (unchanged); (ii) a direct maximization over actual vectors (d_u, d_O in {1, 2, 3}) never
exceeds and attains the exact value; (iii) 32/3 at unit bounds; (iv) exact vs grid on 33 x 3 bound vectors, at most
3.4e-14 apart; (v) dimension-1 value never below a dense 4-variable search that does not use the face reduction; (vi)
never above Theorem S10c's value, strictly below on 32 of 33. Tests: `implementation/tests/test_sens_full_exact.py`.

## B. Check #13: B_tot re-derived for the full-record circuit (decision: re-derive, implement, re-measure if needed)

**Before.** The measured cost (commit 49b4f7d, `experiments/eng/fullrecord_bench.py`) aggregated the 14 extra entries
(the d_R first moments sum b x_j from R's existing vectors and the d_R(d_R+1)/2 products sum b x_j x_k from 10 extra
vectors b x_j x_k that R uploads, all against O's vector of ones) and released them with the **v3.1 calibration**;
`experiments/v31_more/cost_fullrecord.py` re-evaluated Calibrate with the entry counts increased only.

**Re-derivation (Lemma S10e, `docs/proofs/stats_s7_s10.tex`), following Part A** (Prop. 3.8 error decomposition, Prop.
3.11 term bounds, Theorem 3.12, Lemma 4.3 centre sensitivity, Prop. 4.5 decoding offset, Prop. 8.1):

- (a) **B_tot**: R's plaintexts enter only the centre, never an error term, so no bound on R's vectors enters B_tot;
  the circuit enters only through |E| (+ n_A = d_R(d_R+3)/2 = 14) and the row bound Gamma_E (+ n_A, O's vector of
  ones, through M_V in B_1). The check item's premise that the U-side bound B_R^2 enters B_tot does not hold.
- (b) **Delta_x** (sensitivity of the centre): the U-side bounds enter nu_U (+ d_R B_R^2 + d_R(d_R+1)/2 B_R^4), and the
  full-record adjacency replaces R's row as well, which adds Omega_U nu_dU + sqrt(N) Omega_V nu_Vmax to the bracket of
  Lemma 4.3 (nu_dU <= 2 nu_U) and doubles epsilon_x.
- (c) **decoding offset**: nu_U, Gamma_E, |E| of the full-record circuit, zeta_E^2 + B_R^4; S_max unchanged.

Implemented in `implementation/vfr/btot.py` (`CircuitParams.fullrecord`, `n_A`, `nu_V_max`, `epsilon_x`; the v3.1
circuit is unchanged) and `dp.calibrate(..., fullrecord_sens=(Delta, Delta_noyy, Delta_G))` (not a protocol mode).
Tests: `implementation/tests/test_fullrecord_btot.py`. Numbers: `experiments/eng/fullrecord_btot.py` ->
`reports/eng/fullrecord_btot.json` (key_numbers.md C).

**Do flooding and the parameters change? Yes, slightly.** B_tot rises by 0.15 (stage 2) and 0.18 bits (stage 1), the
same as the entries-only re-evaluation (to 1e-4 bits); Delta_x rises by 1.7 bits but stays 2^-33 of the main term.
The v3.1 stage-2 noise floods the v3.1 bound with only 0.02-0.03 bits to spare, so it does **not** flood the
full-record B_tot: the benchmark path of 49b4f7d released stage 2 below the flooding condition. With the full-record
circuit's own calibration (its own sensitivities and B_tot): kappa 40, N and the modulus chain unchanged, the scale one
grid step (1/32 bit) higher (Omega_f 2^62.625 -> 2^62.656 at eps = 1, setting I; 2^62.750 -> 2^62.781 at the
benchmark agreement), q0 needs 85 of 119 bits.

**Cost re-measured** with the full-record calibration (`python experiments/eng/fullrecord_bench.py`, now calibrating
the full-record path on its own; `--calib v31` reproduces the first version): see key_numbers.md D.

Result: the cost does not change. Back to back on a shared machine (load 8-12), the full-record calibration gives
aggregation x1.19 / x1.24 at 16k / 64k rows and a whole run x1.10 / x1.13, against x1.26 / x1.21 and x1.13 / x1.12 for
the control with the v3.1 calibration; uploads and traffic are byte-identical (+10 / +40 MB, x1.15 / x1.46). The
idle-machine factors of 49b4f7d (x1.21 / x1.15, x1.08 / x1.09) therefore stand; `reports/eng/fullrecord.json` keeps them, and `reports/eng/fullrecord_fullcalib.json`
holds the loaded-machine re-measurement. The noiseless test decryption
of the full-record path with its own calibration returns triu A to 6e-12.

**Remark kept (not a check item).** A secure-aggregation protocol of the kind of Karr et al. or Gascón et al. would
have its own cost, which is not measured (paper block F03).

## Reproduce

```bash
export WANG_REPO=/path/to/optimal_dp_linear_regression        # Wang's repository (commit a14dbe5 used here)
python experiments/baselines/sens_full.py check                 # ~25 min (the grid cross-checks)
python experiments/baselines/real_full.py sens                  # exact vs grid on every dataset/fold, ~10 min
python experiments/baselines/real_full.py benchmark             # ~30 min on 4 cores
python experiments/baselines/figures_base.py && python experiments/baselines/tables_base.py && python experiments/baselines/tables_base.py latex
python experiments/eng/fullrecord_btot.py                       # B_tot and Calibrate, three circuits
OMP_NUM_THREADS=1 python experiments/eng/fullrecord_bench.py --out reports/eng/fullrecord_fullcalib.json   # cost, full-record calibration
OMP_NUM_THREADS=1 python experiments/eng/fullrecord_bench.py --calib v31 --out reports/eng/fullrecord_v31calib_control.json
python experiments/baselines/apply_baselines_draft.py --draft paper/drafts/fullrecord.tex --check
cd implementation && python -m pytest -q
```

sympy (1.14 here) is needed for Lemma S10d's enumeration; numpy 2.4.6, scipy 1.17.1, matplotlib 3.11.2 (figures).
