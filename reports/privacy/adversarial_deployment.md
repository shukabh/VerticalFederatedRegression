# Adversarial-parties & deployment risk review — Scenario B

Target: two-party vertical-federated OLS, Scenario B (researcher **R** holds `X_R`,
IDs and all secret keys; organization **O** holds `X_O`, response `y`, IDs). Paper:
*Privacy-Preserving Vertical Federated Linear Regression when the Organization Holds
the Response* (working draft, 31 Aug 2026). Code reviewed (read-only):
`scenario_b/party_r.py`, `party_o.py`, `run_protocol.py`,
`calibrate_hyperparameters.py`, `generate_vfl_data.py`.
`psi_common.py` / `phase1_common.py` / `he_backend.py` were **not** provided; where a
claim depends on them it is flagged.

Demos backing the quantitative claims:
`reports/privacy/demos/adversarial/{A1_onehot_extraction, A2_whole_db_and_averaging,
A3_psi_enumeration, A4_malicious_O_integrity}.py` (pure-numpy local simulations of O's
exact Phase-4 arithmetic; no networking, no crypto, no exploit code against anything
outside the simulation).

---

## Executive summary

The paper is explicit that it assumes **semi-honest** parties (Def. 1). This review
shows how load-bearing that assumption is and how thin the deployment around it is.

- **The DP guarantee is not robust to a malicious R at all.** O adds a fixed absolute
  Gaussian noise (σ ≈ **1526** for the paper's own example bounds `B_R=B_O=3, B_y=20,
  ε=1, δ=1e-5`), calibrated to a sensitivity that *assumes* `b∈{0,1}` and
  `‖x_R,i‖≤B_R`. But `b` and `Xdot_R` reach O **encrypted**, so O cannot check either.
  A malicious R sends a scaled one-hot column and divides the DP noise out: recovery
  error falls as σ/scale. At scale 1e6 an individual's exact O-features **and** their
  response `y` (e.g. income) are recovered to 3-4 decimals (A1). Sweeping columns and
  runs reconstructs O's **entire** database in ⌈n_O/d_R⌉ runs, and there is **no rate
  limit or DP-budget ledger** at O (A2). This is critical and, in the statistical-
  agency setting, catastrophic.
- **PSI is an unrestricted membership-and-row-index oracle.** R chooses the identifiers
  it queries; nothing binds them to an authorised cohort. R can test whether any known
  SIN is in O's administrative dataset (1 slot) and, on a hit, gets O's row index —
  the exact handle the A1 extraction needs to read that identified person's record
  (A3). Some of this is reachable while *formally following the protocol*.
- **R cannot detect a malicious O.** There is no integrity proof on O's reply; O can
  suppress a coefficient, misalign records or drop matches and bias the published model
  arbitrarily (A4).
- **The transport is unsafe independently of the crypto.** Peer bytes are
  `pickle.loads`-ed (arbitrary code execution) and the channel has no TLS or
  authentication, so a MITM substitutes R's public key and reads O's aggregates and
  PSI replies in the clear. The shared `dp_params.json` is generated by a process that
  reads *both* parties' raw data and is integrity-unprotected.

Net: the implementation faithfully realises the *semi-honest* protocol, but offers
**no** malicious- or even covert-security, and the deployment scaffolding (pickle,
plain TCP, shared config, on-disk oracle files) would fail an agency security review on
its own. Priorities: kill the input-amplification channel (A1/A2/A5), authenticate and
encrypt the channel and stop using pickle (A9/A10), and add a query/budget ledger and
input certification (A3/A4).

Severities: **critical** = individual-level raw data or code execution; **high** =
systematic bias or broad leakage; **medium/low** as noted. "In semi-honest model?"
asks whether the paper's own threat model (Def. 1-4) already covers/excludes the
attack.

## A1 — Scaled one-hot single-record extraction (malicious R)

- **Severity: CRITICAL.**
- **In semi-honest model? No** — R deviates by sending inputs that are not the PSI
  result / are out of the committed norm bound. But O *cannot detect* the deviation,
  and the entire DP claim rests on it not happening.
- **Location:** paper §5 (sensitivity assumes `b∈{0,1}`, `‖x_R,i‖≤B_R`; "R must commit
  to B_R at setup, since O cannot see X_R"); `party_o.py:105-131` (O aggregates
  `ct_xdot`, `ct_b` blindly and adds a fixed scalar noise); `party_r.py:116-118` (R
  freely constructs `Enc(b)`, `Enc(Xdot)`).
- **Attack sketch.** O computes, per eqs. (3)-(4), `C[j,k]=Σ_i Xdot[i,j]·X_O[i,k]` and
  `c_R[j]=Σ_i Xdot[i,j]·y_i`, then adds `N(0,σ²)`. R sets column 0 of `Xdot` to a
  one-hot on target row `i*` with amplitude `s` (all other entries 0). Then
  `C[0,k] = s·X_O[i*,k] + noise`, `c_R[0] = s·y_{i*} + noise`. R divides by `s`:
  `X̂_O[i*] = X_O[i*] + noise/s`, `ŷ_{i*} = y_{i*} + noise/s`. The DP noise is a fixed
  σ; the signal is amplified by `s`, so effective error is σ/s → 0.
- **What leaks, to whom.** R learns individual `i*`'s **exact** O-side feature vector
  and response `y` — the most sensitive quantity in the protocol (the administrative
  outcome). `i*` can be any O row, matched or not (`b` is never checked either), and
  can be tied to a real identity via A3.
- **Evidence (A1 demo, σ=1526.20).** Recovery error vs scale for a target's
  `x_O`/`y`:

  | scale s | ‖x̂_O−x_O‖ | \|ŷ−y\| | rel err |
  |--------:|-----------:|--------:|--------:|
  | 1       | 2955.7     | 216.3   | 2.5e+03 |
  | 1e2     | 40.5       | 13.5    | 3.5e+01 |
  | 1e4     | 0.404      | 0.083   | 3.5e-01 |
  | 1e6     | 0.0033     | 0.0014  | 2.8e-03 |
  | 1e8     | 2.8e-05    | 1.7e-05 | 2.4e-05 |

  At `s=1`, one legitimate-magnitude probe leaves the record buried in noise (DP works).
  At `s≥1e4` the record is read out cleanly. CKKS `scale_bits=50` leaves ample headroom
  for `s≈1e4–1e6` against `y∼15`, so finite CKKS precision does not save O.
- **Mitigation & cost.** No cheap fix fully closes this because O cannot bound R's
  encrypted magnitude under a depth-1 circuit.
  - *Proof of well-formed input (real fix):* R attaches a zero-knowledge proof that
    each `Enc(Xdot[i,·])` encrypts a vector with `‖·‖≤B_R` and that `Enc(b)` is binary
    and equals the certified PSI output. Lattice-based ZK range/binary proofs on RLWE
    ciphertexts exist but are **expensive** (large proofs, seconds-per-ciphertext,
    substantial engineering); this is the price of malicious security.
  - *Structural (agency-practical):* run O's aggregation inside O's trusted execution
    environment / secure enclave where R submits vetted queries rather than opaque
    ciphertexts, plus input certification (A3). Cheaper operationally, moves trust to
    the enclave.
  - *Detection-only, weak:* O cannot see plaintext so cannot detect a one-hot; O-side
    normalisation of `Xdot` under HE is not possible at depth 1. Do **not** rely on σ
    alone.
- **Confidence: high** (demonstrated numerically against the code's own σ).

## A2 — Whole-database reconstruction; no budget ledger (malicious R)

- **Severity: CRITICAL.**
- **In semi-honest model? No** for the scaled version; the *no-ledger* aspect (A4) is
  partially in-model.
- **Location:** `party_o.py:36-137` (one-shot process, no persistent state across
  invocations, no counter, no rate limit); `party_r.py` re-runnable at will.
- **Attack sketch.** Each run, R packs `d_R` one-hot columns (amplitude `s`) on `d_R`
  distinct target rows and reads `d_R` full O-records exactly (A1 applied per column).
  `⌈n_O/d_R⌉` runs cover every row. Nothing at O caps the number of runs or tracks
  cumulative privacy loss.
- **What leaks.** The **entire** O database (`X_O`, `y`) — every individual's
  administrative record.
- **Evidence (A2 demo, Part 1).** `n_O=60, d_R=10`: **6** runs reconstruct the whole
  matrix, relative error `‖X̂−X_O‖/‖X_O‖ = 1.8e-04`, `‖ŷ−y‖/‖y‖ = 1.5e-05`. Scaled to
  an agency (`n_O=5,000,000, d_R=10`): **500,000** runs, unbounded because there is no
  ledger.
- **Mitigation & cost.** A1's proof-of-well-formed-input closes the scaled variant. In
  addition: a **persistent query/budget ledger at O** (per-R cumulative ε, run count,
  cool-downs) — modest engineering, essential regardless. Cap the number of releases
  per approved study.
- **Confidence: high.**

## A3 — PSI membership + row-index oracle over an unrestricted query set (malicious R)

- **Severity: HIGH.**
- **In semi-honest model? Partially yes.** The paper treats the intersection as
  legitimately revealed to R (Def. 4) and places **no restriction on which IDs R
  submits**, so enumeration/targeted membership is reachable while formally following
  the protocol. Fabricating a query set is the only "deviation," and even that is
  within a semi-honest R's input choice.
- **Location:** `party_r.py:66-95` (R chooses the IDs in its cuckoo tables and streams
  as many batches as it likes in one session); `party_o.py:94-96` (O returns a
  zero-test `s_j` and the **label** `q_j` = O's canonical row index per match);
  `party_r.py:92-94` (R recovers `sigma_map[k] = O-row-index`).
- **Attack sketch.** R submits arbitrary/enumerated identifiers. For each, O reveals
  membership and, on a hit, O's row index. O only ever learns `n=|I|` (linkage
  privacy), so it cannot see that R is probing non-cohort people.
- **What leaks.** (1) Membership of any queried person in O's administrative dataset —
  itself sensitive for tax/benefit/health enrolment. (2) The O row index of each hit,
  which is the exact handle A1 needs to read that identified individual's record. PSI
  gives the *who*; A1 gives the *what*.
- **Evidence (A3 demo).** BFV `ring_dim=num_bins=16384`, cuckoo capacity
  `⌊0.9·16384⌋=14745` IDs/batch. Targeted membership of a known SIN: **1** slot. One
  province-sized block (1e7 SINs): **679** batches. Full 9-digit SIN space (1e9):
  **67,820** batches — heavy but offline-feasible; targeted probing is trivial.
- **Mitigation & cost.** **Input certification of R's cohort:** the authorised ID list
  (ethics-approved population) is signed by a trusted third party; O runs PSI only
  against R's committed, signed set and refuses arbitrary queries — cheap and standard
  for agency data access. Combine with the A2 ledger (limit queries) and the A4 O-side
  secret permutation so returned indices carry no ordering signal.
- **Confidence: high** (counts are arithmetic; the label-index behaviour is read
  directly from the code).

## A4 — Repeated-run noise averaging & unaccounted composition (malicious *or* careless R)

- **Severity: HIGH.**
- **In semi-honest model? Partially yes** — a semi-honest R that legitimately retrains
  also blows the budget; DP composition across runs is simply not accounted anywhere.
- **Location:** `party_o.py:110` draws **fresh** noise each invocation
  (`np.random.default_rng()`); no cross-run state; paper §7 lists "end-to-end privacy
  ledger" as *future* work.
- **Attack sketch.** R runs the protocol N times with the **same well-formed, in-bounds**
  `b`, `Xdot` and averages the N decrypted aggregate sets. Each run's noise is
  independent `N(0,σ²)`, so the average has stdev σ/√N → the exact noiseless
  sufficient statistics (`B, C, c_R, c_O, yᵀy`) are recovered.
- **What leaks.** The exact non-private second-order sufficient statistics of O's data
  on the matched cohort (and thus exact OLS), with no scaling and no malformed input.
- **Evidence (A2 demo, Part 2).** Empirical stdev of the `c_R` estimate tracks σ/√N:
  N=1 → 2485, N=100 → 161 (≈152.6), N=1000 → 47.2 (≈48.3). Recovery precision is
  unbounded in N; O keeps no state to notice.
- **Mitigation & cost.** The A2 ledger doubles as the fix: a persistent per-study
  privacy accountant at O that composes ε across every release and refuses once the
  budget is spent. Modest engineering; mandatory for any real DP deployment.
- **Confidence: high.**

## A5 — R controls all Phase-1 inputs and metadata; O validates nothing (root cause / malicious R)

- **Severity: HIGH** (enabler for A1/A2; called out separately because it is the fixable
  root cause).
- **In semi-honest model? No.**
- **Location:** `party_o.py:103-106` — O reads `d_R, d_O, n_O` and the ciphertexts
  straight from R's Phase-1 messages and trusts them; `party_r.py:115-118`.
- **Attack sketch.** Beyond A1's values, R lies about metadata: inflate `d_R` to pack
  more one-hot probe columns per run (more records per run in A2); declare `n_O` /
  dims inconsistently; send `Enc(b)` unrelated to the PSI result to probe unmatched
  rows. O has no cross-check that `b` is the PSI output, that `Xdot` is zero off the
  match set, or that `d_R` matches setup.
- **What leaks.** Amplifies A1/A2 (higher extraction throughput; probing arbitrary
  rows).
- **Mitigation & cost.** Pin `d_R, d_O, n_O` from the signed `dp_params.json` (not from
  R's message) and reject mismatches — near-zero cost, do immediately. Bind `Enc(b)` to
  the PSI transcript (the PSI stage already produced the matched set; carry a commitment
  forward). Full closure needs A1's ZK well-formedness proofs.
- **Confidence: high.**

## A6 — Malicious O: undetectable output tampering / model biasing

- **Severity: HIGH.**
- **In semi-honest model? No.**
- **Location:** `party_o.py:112-133` (O alone computes the O-blocks and just pickles &
  sends them; **no MAC, no proof of correct computation**); `party_r.py:119-137` (R
  decrypts, assembles, solves with no integrity check). R has no independent view of
  O's data.
- **Attack sketch.** O returns fabricated aggregates. E.g. zero the cross-terms and
  moment for R's headline feature (`C[0,:]=0, c_R[0]=0`) so its coefficient collapses;
  R concludes "R's feature has no effect," the opposite of the truth. `B` need not be
  PSD (Remark 1), so R cannot even use definiteness as a sanity check.
- **What leaks / harm.** Integrity, not confidentiality: O silently biases the
  **published** model — serious for a research finding. (O still learns nothing about R:
  O never holds `sk`; see A8 for the one narrow channel.)
- **Evidence (A4 demo).** True R-feature-0 coefficient 2.00; honest fit 2.01;
  O-tampered fit −0.06. R cannot distinguish the tampered fit from a legitimate noised
  one.
- **Mitigation & cost.** Verifiable computation / proof that the returned ciphertexts
  are the prescribed circuit on O's committed data (ZK or a committed-input HE
  transcript) — **expensive**. Cheaper partial controls: O commits to `X_O, y` up front
  (hash/commitment) and later opens for audit; publish enough for R to run consistency
  checks (e.g. `yᵀy≥0`, `B⪰` bounds, cross-run stability). Covert/accountable security
  (detect-and-punish) is more realistic than full malicious security here.
- **Confidence: high.**

## A7 — Malicious O: PSI label poisoning & match dropping

- **Severity: MEDIUM-HIGH.**
- **In semi-honest model? No.**
- **Location:** `party_o.py:81-96` (O forms the label payload `q_j` and the zero-test
  `s_j`); `party_r.py:92-100` (R trusts `q_j` as the row index and silently drops any
  label outside `[0,n_O)`).
- **Attack sketch.** (a) O returns wrong row indices → R aligns `X_R` to the wrong O
  records → arbitrary, undetectable bias. (b) O returns a non-zero `s_j` on a true
  match → that individual is dropped → selection bias. (c) O returns out-of-range
  labels → `party_r.py:99` silently discards, shrinking the cohort. R's only "check" is
  a match **count** against a ground-truth `sigma.csv` that exists **only in the
  simulation harness** (`run_protocol.py:32-33`), never in deployment.
- **What leaks / harm.** Systematic, undetectable bias / cohort manipulation of the
  published model.
- **Mitigation & cost.** Authenticate the PSI transcript and have O commit to its
  `id↔row` map; verify alignment by having R spot-check a few known controls; combine
  with A6's committed-input approach. Moderate cost.
- **Confidence: medium-high** (mechanism read from code; A4 demo shows the bias
  magnitude for misalignment).

## A8 — Malicious O: selective-failure / abort inference channel

- **Severity: LOW-MEDIUM.**
- **In semi-honest model? No.**
- **Location:** `party_o.py:79-96` (O can craft per-slot replies); `party_r.py:89-106`
  (R's decryption, label lookup and progression to Phase 1 depend on reply
  well-formedness; R aborts on cuckoo failure / bad state).
- **Attack sketch.** O makes the zero-test or a malformed ciphertext fire only for a
  targeted slot; whether R aborts, errors, or proceeds (and its subsequent messages)
  then depends on whether R's private ID landed in that slot — a classic
  selective-failure oracle leaking bits about R's ID set. Bandwidth is low here (R's
  Phase-1 message count is fixed regardless of match count, so the main observable is
  abort/continue and timing), and O already learns `n`, so incremental leakage is
  small.
- **What leaks.** A few bits about membership of specific IDs in R's set (which O is not
  supposed to learn beyond `n`).
- **Mitigation & cost.** Constant-time, abort-uniform R behaviour (never branch
  observably on decrypted PSI content); authenticate transcripts so malformed replies
  are rejected uniformly. Low cost once the channel is authenticated (A10).
- **Confidence: medium** (channel is real; exact exploitability depends on the
  unprovided PSI code and R's error handling).

## A9 — Pickle deserialization of peer data → arbitrary code execution (deployment)

- **Severity: CRITICAL.**
- **In semi-honest model? No** (out of scope of the paper; a system flaw).
- **Location — confirmed `pickle.loads` on bytes received from the peer:**
  `party_r.py:75, 89, 119`; `party_o.py:65, 79, 103, 106`. Additionally
  `party_o.py:105` and the `*_from_public` / `ct_from_bytes` calls
  (`party_r.py:90-91,122`, `party_o.py:64,102,105`) deserialize peer bytes through the
  unprovided `he_backend`; if those also use pickle they are further RCE sinks.
- **Attack sketch.** `pickle.loads` executes `__reduce__` during unpickling, so any
  bytes a peer (or a MITM, see A10) sends can run arbitrary code on the receiver. Party
  R is a **listening socket server** (`party_r.py:50-54`) — anyone who connects to its
  port can trigger this. Party O — a national statistical agency — would execute
  arbitrary code from whoever it connects to.
- **What leaks / harm.** Full remote code execution on either party's host; total
  compromise of O's data store is possible.
- **Mitigation & cost.** Replace pickle with a **safe, schemad serializer** (protobuf /
  msgpack / JSON + explicit typed decoders; serialize ciphertexts via the HE library's
  own byte API). Low-to-moderate engineering; non-negotiable before any real
  deployment.
- **Confidence: high** (lines confirmed).

## A10 — No TLS / authentication → MITM key substitution (deployment)

- **Severity: CRITICAL (confidentiality) / HIGH.**
- **In semi-honest model? No.**
- **Location:** plain TCP throughout (`party_r.py:50-54`, `party_o.py:58-60`); public
  keys sent **unauthenticated** (`party_r.py:64` BFV `public_blob`, `party_r.py:114`
  CKKS `public_blob`); no certificates, no channel binding.
- **Attack sketch.** A network MITM replaces R's public key with the attacker's on the
  wire. O then encrypts all Phase-1 aggregates (and the PSI replies are computed)
  under the attacker's key; the MITM decrypts O's `B, C, c_R, c_O, yᵀy` and PSI
  outputs in the clear, optionally re-encrypting under R's real key to stay invisible.
  The MITM can also tamper (A6/A7) at will.
- **What leaks / harm.** All of O's released aggregates and PSI replies to a passive
  network attacker; full loss of confidentiality despite the HE.
- **Mitigation & cost.** Mutual-TLS with pinned certificates (or an authenticated key
  exchange binding the HE public keys), so public keys cannot be substituted. Low cost,
  standard; pairs with A9's safe serialization.
- **Confidence: high.**

## A11 — Shared `dp_params.json`: cross-party leakage + unprotected integrity (deployment)

- **Severity: HIGH.**
- **In semi-honest model? No** (the paper assumes public constants are agreed honestly;
  the code's generator is not).
- **Location:** `calibrate_hyperparameters.py:243-278, 299-336` — `calibrate()` reads
  `X_R`, `X_O` **and** `y_O` in one process and writes into `dp_params.json` (which
  **both** parties read at `party_r.py:26`, `party_o.py:37`): 0.99-quantile suggested
  bounds, per-block **clip rates**, and standardization **centers/scales**. Integrity
  of the file is unprotected (no signature).
- **Attack sketch.** (1) *Trust:* whoever runs calibration sees both raw datasets — a
  single point that defeats the federation. (2) *Cross-party leak:* R receives data-
  derived statistics of O's `X_O, y` (quantile bounds, clip rates) **outside** the DP
  budget; O receives R's feature means/SDs. (3) *Integrity:* R or a MITM edits `sigma`
  downward (or bounds), silently weakening/voiding the (ε,δ) guarantee; O reads and
  uses it without verification. (`--scale_source committed` also silently falls back to
  data values while setting `dp_valid=True` — see `code_review.md` finding 2.)
- **What leaks / harm.** O-data statistics to R off-budget; DP silently weakened;
  requires an all-seeing trusted setup party.
- **Mitigation & cost.** Split calibration by party (R commits `B_R` + its own scaling;
  O commits `B_O, B_y, σ`); exchange only **public** constants, each **signed** by its
  owner; both parties verify signatures before use; never derive bounds/scales from the
  live sample. Low-to-moderate cost; also see `code_review.md` finding 2 for the
  code-level version.
- **Confidence: high.**

## A12 — Oracle & intermediate files on disk; verbose logs (deployment)

- **Severity: MEDIUM.**
- **In semi-honest model? No** (out of scope).
- **Location:** generator writes ground-truth oracle files into the shared `data_dir`:
  `sigma.csv` (the **true matching**), `y.csv`, `beta_true.csv`, `b.csv`,
  `X_R_aligned.csv` (`generate_vfl_data.py:293-334`). Harness reads them all
  (`run_protocol.py:22-28`). R writes `beta_private.csv`, `beta_original_scale.csv`,
  `run_summary.json` (contains `yty`) (`party_r.py:169-176`); both parties print clip
  rates and `yᵀy` to stdout (`party_r.py:44,177`, `party_o.py:56`).
- **Attack sketch.** In a real deployment those generator files must not exist — but the
  pipeline reads from the same `data_dir`, so if it is shared/misconfigured the exact
  linkage (`sigma.csv`), O's response (`y.csv`), R's aligned data and selection
  (`X_R_aligned.csv`, `b.csv`) sit in plaintext on disk. Logs shipped to central logging
  leak per-party statistics (clip rates, `yᵀy`).
- **What leaks / harm.** The entire ground truth (matching + `y`) if the oracle files
  are present; per-party stats via logs.
- **Mitigation & cost.** Strictly separate the generator/oracle from the deployment
  data directory; each party keeps only its own inputs; scrub/parameterise logs (no raw
  stats, no `yᵀy` to shared logs); document that `sigma.csv`/`y.csv`/`beta_true.csv`/
  `b.csv`/`X_R_aligned.csv` are simulation-only. Low cost.
- **Confidence: high.**

## A13 — DoS / robustness (deployment)

- **Severity: MEDIUM.**
- **In semi-honest model? No.**
- **Location:** no socket timeouts anywhere (`party_r.py`, `party_o.py`); unbounded
  message sizes (length-prefixed `recv_msg`, impl in unprovided `psi_common`); open
  listening port with no auth (`party_r.py:50-54`); `time.sleep(2.0)` startup race
  (`run_protocol.py:14`).
- **Attack sketch.** A peer that stalls hangs the other forever (no timeout). A large
  length prefix can exhaust memory. Anyone can connect to R's port to consume resources
  or deliver an A9 pickle payload. If R's imports exceed 2 s, O's connect races and the
  run fails.
- **What leaks / harm.** Availability; also the entry point for A9/A10.
- **Mitigation & cost.** Socket timeouts + a hard cap on message size + retry-with-
  backoff on connect (replace the fixed sleep) + bind the listener behind mTLS (A10) so
  only the authenticated peer can connect. Low cost.
- **Confidence: high.**

## A14 — Weak RNG and fixed cuckoo seed (deployment)

- **Severity: LOW.**
- **In semi-honest model? No** (crypto-hygiene; overlaps `code_review.md` finding 9 and
  the DP report).
- **Location:** `party_r.py:66` `np.random.default_rng(0)` — **fixed** seed for cuckoo
  hashing (deterministic, reproducible bin layout across runs); PSI masks and DP noise
  use NumPy PCG64 (`party_o.py:77,92-93,110`), not a CSPRNG; the DP noise is a
  floating-point Gaussian (Mironov 2012 leakage).
- **Attack sketch.** A predictable cuckoo layout aids an adversary reasoning about slot
  placement; a non-CSPRNG mask/noise stream is not cryptographically unpredictable; the
  float Gaussian has low-bit structure that can erode the formal DP bound. Individually
  low impact here.
- **What leaks / harm.** Marginal; strengthens other attacks rather than standing
  alone.
- **Mitigation & cost.** Use OS entropy / `secrets` for masks, a fresh unpredictable
  seed for cuckoo, and a discrete/snapped Gaussian for the DP noise (paper §7 item iv).
  Low cost.
- **Confidence: medium** (float-Gaussian and PCG64 impacts are established in the
  literature; exact magnitude is the DP report's domain).

## Prioritized fix list

1. **Kill the input-amplification channel (A1, A2, A5).** Require ZK proofs that
   `Enc(Xdot)` rows are norm-bounded and `Enc(b)` is binary and equals the PSI output,
   or run O's aggregation in an enclave; pin dims from signed config, not R's message.
   *This is the difference between "DP holds" and "DP is a formality."*
2. **Safe serialization (A9).** Remove every `pickle.loads` on peer bytes
   (`party_r.py:75,89,119`; `party_o.py:65,79,103,106`) — schemad decoders only. RCE.
3. **Authenticated, encrypted channel (A10).** mTLS with pinned certs / authenticated
   key exchange so HE public keys cannot be MITM-substituted.
4. **Query & DP-budget ledger at O (A2, A4).** Persistent per-study accountant: compose
   ε across releases, cap runs, rate-limit; refuse when the budget is spent.
5. **Input certification of R's cohort (A3).** PSI only against a third-party-signed
   authorised ID list; refuse arbitrary queries. Add O-side secret permutation so
   returned indices carry no ordering (also `code_review.md` finding 4).
6. **Split & sign calibration; stop the cross-party leak (A11).** Each party commits and
   signs its own public constants; verify before use; never derive bounds/scales from
   the live sample.
7. **Integrity of O's output (A6, A7).** Commit O's `(X_O,y)` and its `id↔row` map up
   front; move toward verifiable computation or at least covert/accountable security;
   let R spot-check known controls.
8. **Separate oracle/simulation files from deployment data; scrub logs (A12).**
9. **Robustness (A13):** socket timeouts, message-size caps, connect retry (drop the
   `sleep`), listener behind mTLS.
10. **RNG hygiene (A14, A8):** CSPRNG masks, unpredictable cuckoo seed, discrete
    Gaussian, abort-uniform R behaviour.

Notes: A1/A2/A5 have no cheap complete fix — full malicious security here is expensive
(ZK on ciphertexts / verifiable HE) and the honest near-term path for a statistical
agency is likely enclave-based aggregation plus certification, ledgering and
authenticated transport (items 2-6), which raise the bar to covert/accountable security
even if not full malicious security.
