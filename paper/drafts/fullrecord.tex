%B-BEGIN F01 Proof sketch of prop:sens_full: the dimension-one case is exact (Lemma S10d), and so is every value
%OLD| so the supremum has a closed form computed by exact enumeration, as for Proposition~\ref{prop:sens} (proofs, Part~B, Theorem~S10c); for a block of dimension one that value is a valid, conservative bound. %NEW-BEGIN
so the supremum has a closed form computed by exact enumeration, as for Proposition~\ref{prop:sens} (proofs, Part~B, Theorem~S10c). For a block of dimension one, as $\Rp$'s block of 3droad and tamielectric, the bracket is exact for that block too and convex in $\lambda^2$ when $(u, u')$ or $(y, y')$ is scaled by $\lambda$, so a maximizer lies on one of five faces of the box of $(u, u', y, y')$. On each face the bracket is piecewise polynomial in at most two variables, and the supremum is the largest value over a finite set of vertices, stationary points on edges and interior stationary points (found from resultants), which the code enumerates in exact rational arithmetic (proofs, Part~B, Lemma~S10d). Every value reported below is exact in this sense and rounded up by a relative $10^{-12}$. The numerical maximization used before (a dense grid refined by local search) agrees with it to $2 \cdot 10^{-15}$ on the bounds of all 29 datasets, so no reported number changes.
%NEW-END
%B-END F01

%B-BEGIN F02 Cost bullet: B_tot re-derived for the full-record circuit; its own calibration
%OLD| With the larger entry counts, Calibrate raises $\log_2 B_{\mathrm{tot}}$ by $0.15$--$0.18$, with the same $\kappa$ and $\sigma$.
%NEW-BEGIN
We re-derived the worst-case error bound, the sensitivity of the centre and the decoding offset for this circuit (proofs, Part~B, Lemma~S10e). $\Rp$'s vectors enter no error term, so $B_{\mathrm{tot}}$ changes only through the $14$ more entries and the vector of ones in $\Op$'s row bound: $\log_2 B_{\mathrm{tot}}$ rises by $0.15$ at stage~2 and $0.18$ at stage~1, as the earlier re-evaluation with the larger entry counts gave. The bound $|b\,x_jx_k| \le B_R^2$ on the new vectors and the replacement of $\Rp$'s row enter only the sensitivity of the centre ($\Delta_{x,2}$ from $2^{27.6}$ to $2^{29.2}$, about $2^{-33}$ of the main term) and the decoding offset. The v3.1 stage-2 noise floods the old bound with a margin of only $0.03$ bits and so does not flood the new one; the full-record releases are therefore calibrated on their own, with their own sensitivities. Calibrate keeps $\kappa = 40$, $N$ and the modulus chain and raises the scale by one grid step ($\log_2\Omega_f$ from $62.625$ to $62.656$ at $\varepsilon = 1$ under setting I). The operations are the same at other plaintext scales, so the cost should not change, and it does not: re-measured with this calibration, back to back with a control run that keeps the v3.1 calibration (on a shared machine, so both slower than above), $\Op$'s aggregation grows by $1.19$ and $1.24$ at $16$k and $64$k rows against $1.26$ and $1.21$ in the control, a whole run by $1.10$--$1.13$ in both, with the same upload; the factors above, measured on an idle machine, stand.
%NEW-END
